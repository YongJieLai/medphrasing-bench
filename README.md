# MedPhrasingBench

> **同一个信息点，换一种问法，患者说出来的东西会不会不一样？**
> 本仓库测量这件事、复现它，并把它做成可评测的场景。

> 📌 名字三部分各对应一件事：`Med` 领域 · `Phrasing` 研究对象（怎么问，不是问什么）· `Bench` 交付形态。
> 措辞是一个多维空间，开放性只是其中一维，且不是最有信息量的那一维。见 §2。

---

## 1. 问题

交互式诊断的评测只看终点：诊断对不对。问诊过程被当作获取信息的通道，而不是被评价的行为。于是「穷举所有症状」和「五个问题确诊」同分。

而在真实诊室里，问法是有代价的——它不只改变患者**说多少**，还改变患者**说得准不准**、**有没有答全**。这个代价目前无法被测量，因为主流患者模拟器是门控的：回答只由「问了什么」决定，措辞不进入输出函数。

本仓库要做的，是把「怎么问」变成一个可测量、可复现、可归因的量。

---

## 2. 措辞的维度体系

评价医生提问，不止「开放 / 封闭」。下面四层是可操作化的完整清单，标注了本仓库的覆盖状态。

### L1 形式层：问句长什么样（可规则 + LLM 判定）

| # | 维度 | 取值 | 状态 | 主要作用于 |
|---|---|---|---|---|
| F1 | 开放度 | open / semi / closed / choice | ✅ 已标注 | 披露量 |
| F2 | 问句类型 | wh- / polar / tag / declarative / imperative | 🔶 混在 F1 里 | 披露量、附和 |
| F3 | 复合性 | single / multi | ✅ | 完整性 |
| F4 | 预设负载 | none / weak / strong | ⬜ 待补 | 准确性 |
| F5 | 引导性 | neutral / mild / strong | ✅ | 准确性 |
| F6 | 否定形式 | affirmative / negative / double | ⬜ 待补 | 准确性（答反方向） |
| F7 | 术语密度 | lay / mixed / jargon | ⬜ 待补 | 完整性（听不懂） |

### L2 语用层：问句落在对话的什么位置

| # | 维度 | 取值 | 状态 | 主要作用于 |
|---|---|---|---|---|
| P1 | 追问深度 | surface / deepen / new / revisit | ✅ | 准确性 |
| P2 | 话题管理 | continue / switch / revisit | 🔶 混在 P1 里 | 覆盖度 |
| P3 | 冗余度 | new ask / repeat / re-ask answered | ⬜ | 效率 |
| P4 | 节奏 | 一问一答 / 连珠炮 | 🔶 与 F3 重叠 | 完整性 |
| **P5** | **时机** | **opening / body / closing** | ⛔ **必须补** | **混杂变量，M1 核心** |

### L3 关系层：患者愿不愿意说（**全部空白**）

| # | 维度 | 取值 | 状态 | 主要作用于 |
|---|---|---|---|---|
| R1 | 共情标记 | none / weak / strong | ⬜ 待补 | 披露意愿、披露量 |
| R2 | 面子威胁 | low / mid / high | ⬜ 待补 | 敏感信息（性史、用药、心理） |
| R3 | 正常化 | yes / no | ⬜ 待补 | 披露意愿 |
| R4 | 安抚 / 保证 | yes / no | ⬜ 待补 | 披露意愿 |

### L4 内容层：问什么（**控制变量，不是自变量**）

| # | 维度 | 作用 |
|---|---|---|
| C1 | 信息增益 | 必须控制，否则「问得好」与「问得准」混淆 |
| C2 | 鉴别诊断覆盖 | 同上 |
| C3 | 漏斗顺序 | 与 P5 高度共线 |

### 现有覆盖的问题

**四维全部落在 L1 与 L2，L3 一维未做。** 换句话说，我们目前只测了「信息怎么被取出」，没测「患者愿不愿意给」。

这不是小事：在真实问诊里，最影响披露的往往不是问句形式，而是关系——敏感信息（性史、药物滥用、家暴、心理症状）几乎不因开放式提问而出现，却会因一句共情、一句正常化而出现。只做 L1/L2，测出来的是**信息提取效率**；补上 L3 才是**问诊能力**。

L3 也是与现有工作拉开距离最干净的地方——目前没有任何 LLM 患者模拟器建模「共情 → 披露」。

## 3. 核心假设（按证据强度重排）

| # | 假设 | 类型 | 是否定义性的 |
|---|---|---|---|
| **H1** | 开放度 ↑ → 回答长度 ↑ | **操纵检查** | ⚠️ **是**。是非问只能答「是」，必然短。这条不能当发现，只能证明标注有效 |
| **H2** | 引导性 ↑ → 附和率 ↑（信息被污染） | **核心发现** | 否。附和不等于短，是「说了但没信息」 |
| **H3** | 复合性 ↑ → 漏答率 ↑（信息丢失） | **核心发现** | 否 |
| **H4** | 追问深度 ↑ → 回答精确度 ↑ | **核心发现** | 部分（deepen 本就要求具体化） |
| **H5** | 开放度 ↑ → 溢出率 ↑（说了没被问的） | **核心发现** | 否，但需控制回答长度 |

> 关键区别：H1 说「问得开放，答得长」，这是同义反复；H2/H3 说的是「问得歪，信息被改写了 / 被丢掉了」，这才是临床上有代价的事。**项目的重量应该压在 H2、H3 上，而不是 H1。**

### 因变量：披露的四属性

| 属性 | 度量 | 操作化 |
|---|---|---|
| 量 quantity | 连续 | AIU 数、词数 |
| 准确性 definiteness | 序数 | exact / vague / agree（附和） |
| 完整性 completeness | 0/1 | 是否答全所有子问题 |
| 相关性 relevance | 序数 | on-topic / spillover / off-topic |

## 4. 证据（按强度排序，弱证据在后）

### 4.1 真实语料测量（E1，主力证据）

MTS-Dialog（1501 段真实英文医患对话，逐轮对齐）→ 5425 个「医生提问 → 患者回答」对，规则过滤后 **5325 条**。qwen-flash 主标，8 维 AC1 ≥ 0.77。

| 假设 | 结果 | 显著性 | 定性 |
|---|---|---|---|
| H1 开放度 → 披露量 | 1.32 → 1.93 → 2.48 AIU（closed/semi/open） | p=4.9e-123 | 操纵检查 |
| **H2 开放度 → 溢出率** | 4.9% → 8.1% → **13.2%**（2.7×） | p=3.6e-16 | 核心 |
| **H3 引导性 → 附和率** | 14.2% → 36.1% → **51.6%**（neutral/mild/strong） | p=5.4e-43 | 核心 |
| **H4 复合性 → 漏答率** | 2.8% → **8.0%**（2.9×） | p=3.7e-06 | 核心 |
| **H5 追问 → 精确率** | 23.2% → 69.6% → **74.6%**（surface/new/deepen） | p=4.2e-76 | 核心 |

详见 `docs/step1_results_full.md`。

> ⚠️ **这批结果目前没有控制对话阶段（P5）。** 开场问题天然更开放，开场时患者本来也说得多——「措辞效应」里有多少是「时机效应」，尚未分离。这是 M1 的任务，在它完成前，对外只能写「观测到关联」。

### 4.2 模拟器对照（E3，管线自检）

DDxPlus 50 例 × 6 信息点 × 2 措辞，n=289 配对：开放式溢出 6.997 vs 封闭式 3.630，t=12.02。

> ⚠️ **这是循环论证**：`src/patient.py` 的 system prompt 里直接写了「开放式要多展开、封闭式要简短」。它只证明管线能跑通，不能作为学术证据。保留它是为了说明「如果不做真实数据校准，模拟器实验会长什么样」。

## 5. 与现有工作的分野

| 维度 | 现有工作 | 本项目 |
|---|---|---|
| 研究问题 | 问**什么**（DOCTOR-R1、ProMed、MedClarify） | 怎么**问**（措辞的多维空间） |
| 患者模型 | 门控：问 A 只答 A | 措辞敏感的响应函数 |
| 信息量来源 | 问题数量的函数 | 提问质量的函数 |
| 措辞维度 | 无（或只有 open/closed 二分） | L1–L3 分层体系 |
| 关系维度 | 无 | L3（规划中） |

- 2501.09484（百川 + 人大）：患者模拟器有 `[Provide Information]`，但溢出由**外生随机策略流**决定，与提问质量无关
- MAQuE：Disclosure Control 方向相反，管的是**上限**
- PWP：问句二分 polar/open/statement + β 对齐，但 β 是**真实感旋钮**，不是研究变量
- SAPS：把「反复问模糊问题能套出更多信息」当作**漏洞**去压制
