# 研究简报：交给文献调研 agent 的交接文档

> 目的：本文档是给「调研文献、判断这个方向是否有人做过、我们的站位在哪」的 agent 看的。
> 它必须自包含——读它的人看不到我们的对话历史，所以关键背景、精确的新颖点、已有证据、查重靶点都要写全。

---

## 一、一句话定位

我们在研究交互式医疗诊断里的一个此前未被显式建模的问题：

> **医生「怎么问」（提问措辞），而非「问什么」（内容选择），会改变患者自发披露的信息量、准确性与完整性。**

具体机制是：**患者的信息溢出（spillover）是提问措辞质量的函数**——开放式、有引导性的好问题会触发患者主动说出「未被直接问到的相关信息」，而封闭式、引导式（暗示答案）、复合式问题会抑制披露或降低披露可靠性。

---

## 二、核心形式化（我们的 setting 增量）

交互式诊断中，现有所有患者模型的「回答函数」本质都是**门控（gated）**：

```
现有门控式：  answer = gate(question)          # 问 A 只答 A，信息量 = 问题数量的函数
我们的 setting： answer = gate(question) + spillover(question_style) + noise
                                        # 溢出是「提问措辞/开放度」的函数，信息量 = 提问质量的函数
```

关键：`spillover` 这一项是**内生**的——由提问的措辞（开放度、引导性、复合性、追问）触发，而不是外生随机。

---

## 三、精确的新颖点（与现有工作切开的那一行）

我们与现有工作的分野可以用两个正交轴说清：

| | 研究什么 | 代表工作 |
|---|---|---|
| **医生侧（已被卷成红海）** | 问**什么**：选「信息增益最高」的问题 | DOCTOR-R1（ICLR 2026）、ProMed（ACL 2026）、MedClarify |
| **我们（患者侧，空白）** | **怎么**问：同一信息，措辞的开放度/引导性改变患者吐露量 | 本项目 |

具体三层增量：

1. **从「问什么」到「怎么问」**：现有工作全部在优化「问题选择」（选哪个问题信息价值高），没有任何人研究「同一个问题，开放式 vs 封闭式措辞会改变患者吐露的信息量」。

2. **从「外生溢出」到「内生溢出」**：唯一接近我们的是 arXiv 2501.09484（百川+人大），它的患者模拟器已有 `[Provide Information]` 策略（患者会主动多说），但「何时多说」由**随机抽取的对话策略流**决定，**独立于医生提问质量**。我们做的正是把这个外生随机项改成「提问措辞的函数」。

3. **从「单标量披露量」到「四属性披露」**：现有患者模拟器只建模「披露多少」一个标量。我们把患者反应拆成**四个正交属性**——披露量、披露准确性、披露完整性、披露相关性——分别对应不同的提问维度。

### 四维提问 × 四属性披露（我们的测量框架）

| 医生提问维度 | 定义 | 主要影响的患者披露属性 |
|---|---|---|
| **开放度**（open-endedness） | 开放式 vs 半开放 vs 封闭式 | 披露**量**（开放式 elicits more） |
| **引导性**（leadingness） | 是否暗示答案（"胸痛是刺痛吗？"） | 披露**准确性**（引导→患者附和，可靠性下降） |
| **复合性**（multi-barreled） | 一次问多个问题（"发烧、咳嗽、胸痛？"） | 披露**完整性**（患者只答最后一个，漏答） |
| **追问深度**（follow-up） | 是否顺着模糊线索深化 | 披露**准确性/深度**（把"不舒服"深化成"右侧搏动性头痛"） |

## 四、已有证据（截至当前）

### 证据 1：DDxPlus 50 例对照（有循环论证嫌疑，仅供信号参考）

- 数据：DDxPlus（MedExAgent 同源公开库）随机 50 例，每例 6 个信息点，各生成 open/closed 两种措辞。
- 结果：开放式平均溢出 **6.997** 个 AIU（原子信息单元）vs 封闭式 **3.630**，配对 t=12.02，p=3.1e-27，47/50 病例 open>closed。
- **⚠️ 致命弱点**：患者模拟器的 prompt 里直接写了「开放式要多展开、封闭式要简短」，等于把结论写进了前提——这是循环论证，不能作为学术证据，只证明管线可行。

### 证据 2：MTS-Dialog 真实对话测量（正在做的关键一步，用于打破循环论证）

- 数据：**MTS-Dialog**（Ben Abacha et al. 2021，英文真实医患对话，1501 个，逐轮 `Doctor:/Patient:` 对齐，6490 个 doctor-patient 提问-回答对）。
- 方法：对每个提问-回答对，LLM 标注医生提问的 4 个维度 + 患者回答的 4 个属性。
- **P1 双标一致性（200 条，flash 主标 vs plus 核对，Gwet's AC1）已达标**：8 个维度全部 ≥ 0.77，核心维度 openness=0.914、definiteness=0.773、relevance=0.768。
- **全量正式结果（5325 条，已完成，5 个假设全部成立且高度显著）**：

| 假设 | 自变量 | 因变量 | 效应量 | 显著性 |
|---|---|---|---|---|
| 开放度↑ → 披露量↑ | open vs closed | info_units | 1.32 → 2.48（d=-0.979） | p=4.9e-123 |
| **开放度↑ → 溢出↑** | open vs closed | spillover 率 | 4.9% → 13.2%（2.7×） | p=3.6e-16 |
| 引导性↑ → 附和↑ | strong vs neutral | agree 率 | 14.2% → 51.6% | p=5.4e-43 |
| 复合性 → 漏答↑ | multi vs single | 漏答率 | 2.8% → 8.0% | p=3.7e-06 |
| 追问 → 更精确 | deepen vs surface | exact 率 | 23.2% → 74.6% | p=4.2e-76 |

  - 统计：混合效应模型（含 `dialogue_id` 随机效应）+ 卡方检验。
  - **最关键的一条**：开放式提问引发患者「自发溢出未问到的信息」的概率是封闭式的 **2.7 倍**（13.2% vs 4.9%，p=3.6e-16）——这是本项目核心 setting 的实证根基，把之前的循环论证（DDxPlus 50 例 prompt 写死）升级成了真实数据上的经验命题。
  - 详细结果：`docs/step1_results_full.md`。

### 证据的层级（诚实声明）

| 层级 | 内容 | 可信度 |
|---|---|---|
| 已确立 | 「开放式提问 elicits more info」是医学教育教科书常识（Calgary-Cambridge 框架、Beckman & Frankel 1984） | 高（但这是常识，不是我们的贡献） |
| 待确认 | 这个因果在 **LLM 交互式诊断 setting** 里是否被显式建模过 | **这是要调研 agent 查重的核心** |
| 待确认 | 真实对话数据里「措辞→披露」的效应量和显著性（正在测） | 待全量标注完成 |

## 六、需要调研 agent 回答的问题（查重靶点）

请按优先级逐条回答「是否有人做过、做到什么程度、精确差异在哪」：

1. **【最高优先】患者侧「信息披露溢出 / elicitation 作为提问措辞（开放性/引导性）的函数」——是否有人在 LLM 医疗诊断 setting 里显式建模过？** 这是我们主张的核心空白。

2. **开放式 vs 封闭式提问，对「LLM 患者模拟器 / 真实对话」中患者信息披露量的影响**——计算语言学、医学信息学、NLP 领域是否已有实证测量？

3. **「引导性提问 → 患者附和/暗示易感性 → 信息可靠性下降」** 在 LLM 对话 agent 里的建模——法医学/证词心理学里 suggestibility 研究很多，但 LLM 患者模拟器里有没有？

4. **「追问（follow-up）→ 信息精确化」「复合问题（multi-barreled）→ 漏答」** 在医学对话 agent 里的建模。

5. **是否存在「多属性披露（量/准确性/完整性/相关性）」的患者模拟器框架**？还是现有工作都只用「披露量」一个标量？

6. **引用 arXiv 2501.09484 的最新工作**——挖 Semantic Scholar / OpenAlex 的引用网络，看有没有人已经把它的「外生溢出」改成了「提问质量触发」。

7. **反向查证**：是否已有工作明确论证过「开放式提问在 LLM 诊断中不改变或负向改变披露」？如果有，我们的假设可能被推翻。

## 八、站位判断的判定标准（给调研 agent 的收口问题）

请最终回答一个收口问题：

> **「同一个信息、同一个信息增益的问题，开放式措辞 vs 封闭式措辞，是否会改变患者自发吐露的信息量」——这个因果，在 LLM 交互式诊断 setting 里，是否已被任何人显式建模并验证？**

- 若**无人建模** → 我们的核心空白成立，站位是「患者侧信息溢出机制的开创者」。
- 若**有人已建「披露量溢出」** → 我们的差异化退到「四属性披露（尤其准确性/完整性）的多维建模」这一层，需重新评估增量。
- 若**有人已做四属性** → 方向可能已饱和，需要重定向。
